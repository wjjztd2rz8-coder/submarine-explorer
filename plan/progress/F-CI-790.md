## Implementation and timing method

- `helpers/clock.ts`: readiness polls explicitly present one frame per bounded
  clock advance with a short polling interval. Movement callers request 250ms,
  matching `Time.tick()`'s clamp; no game-state injection or input replacement.
- `withClockFrames`: Axe creates/closes a temporary page for `finishRun`; the
  context-wide clock call can race that closure. Watch auxiliary close events and
  retry only a closed-target error coinciding with that event, while verifying
  the main page is alive. Return the original work result/error and fail if the
  game page closed. Three unit tests cover auxiliary recovery, genuine clock/
  main-page failures and audit error propagation. All 15 repeated real a11y
  audits passed after this change. No accessibility rules or scope removed.
- Save soak: retain all four dives, mode switches, twelve restarts, reloads,
  migrations and exact allocation equality. Wait for actual animation frames
  after content/textures load, following the title audit pattern. Sampling also
  observes two frames for disposal/rendering. The >0.05m threshold stays intact.
- Flow site selections now wait for the navigation load event before pumping
  readiness frames; a touch tap can resolve while the outgoing document is still
  active. This additional race surfaced in local validation.
- Debrief/current specs: paused browser clock removes unbounded background WebGL
  work while DOM checks run. Screenshots still render explicit frames. Every
  viewport/site, scan, reward, Journal, current multiplier and exit check remains.
- Onboarding hint readiness now waits for the intended POI to become the actual
  scanner candidate after teleport/cancel, before checking the paused scan HUD.
  The expiry, persistence, visibility and hull-rating assertions remain exact.
- Toast readiness now includes `discovery.loaded`, not only wildlife readiness,
  and presents two frames before the scan-panel check. A DOM-only wait cannot
  update a paused game's HUD; this content-order race surfaced in regression.
  Visibility and overlap assertions remain unchanged.
- Verification: scoped CI timeout of 300s preserves the existing 90-frame sample
  and all geometry/performance assertions; no frames or test cases trimmed.
- `tools/e2e-update-timings.mjs` imports hosted JSON using the same helper source
  and nested title keys as shard discovery. Completed attempt durations are
  summed per test, including retries and timed-out attempts as conservative
  observed costs. Repeated supplied samples are averaged. Interrupted, skipped
  and unexecuted tests retain prior estimates/fallbacks. The importer has a unit
  test for retries, helper keys, skipped/interrupted cases and timeout samples.
- Imported **380 completed test costs** from all 20 shards. Retained older costs
  for cases without new measurements. No local duration substituted for hosted
  data. Refresh after the fixes land because old failure/retry costs deliberately
  overestimate those repaired cases.
- Comparable successful tests show **1.10× median**, **1.02× aggregate** versus
  prior stored durations, so the evidence does not establish uniform 2× slowdown.
  Nevertheless newly measured audits and retry costs make the recalibrated
  20-shard plan (**20.3–20.4 minutes**) too close to the 25-minute cap. Use **30 shards**, the requested
  maximum: **13.5–13.6 minutes estimated per shard**, including the existing
  two-second startup allowance per test. All **456 current tests** remain in
  discovery and are selected exactly once. No global/job timeout or retry increase.
