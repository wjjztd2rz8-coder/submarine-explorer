## Fixed

1. **Home's Journal shortcut stopped working after a briefing cancel or dive exit.** Initial Home handles J / the Journal pad button in `homeStartup.ts`. Returning Home retains the dive runtime, whose input gate replaces sampled actions with frozen input; `discovery.ts` previously recovered the Journal action only when the Journal was already open. Allow the action when Home owns the top overlay too. Gameplay remains frozen; covering dialogs retain ownership and ignored edges do not replay. Both keyboard and gamepad unit cases failed before the fix. Regression coverage: `tests/unit/overlayFocus.test.ts`; fresh-player desktop and 390×844 touch-layout cases in `tests/e2e/d-shell.spec.ts` exercise initial Home, site selection, briefing cancellation, Journal toggle and a covering Settings dialog. The phone case deliberately uses an attached keyboard for J.

2. **Browser Back restored a mission URL over Home with a disposed mission.** Briefing cancellation, Quit, and debrief Home/Dive sites use `history.pushState`; the mission disposes on Home entry. There was no `popstate` handler. Shell history traversal now reloads the selected URL, using the existing boot path. This starts a fresh briefing rather than resuming discarded per-dive state; persisted Journal entries remain saved. The listener belongs to shell teardown. The unit regression failed before the fix. Regression coverage: `tests/unit/homeFocus.test.ts` and the Back/Forward round trip in `tests/e2e/d-shell.spec.ts`.

3. **A modal-consumed key could leave touch controls under keyboard coaching.** Coaching observes keyboard events before overlay dispatch. Touch controls used a separate listener, which never received Escape when a focus trap consumed it. Escape from touch Pause could therefore produce keyboard tutorial labels with the touch dock still active. Touch controls now use the existing shared passive keyboard observer, retaining the existing modifier exclusions and disposal. The unit regression failed before the fix. Regression coverage: `tests/unit/touchControls.test.ts` and a 390×844 case in `tests/e2e/f3-onboard.spec.ts` checking Pause dismissal, hidden touch controls, keyboard device and keyboard coaching.

All changes reuse existing state, navigation and input mechanisms. No HUD element, setting, guidance surface, layout offset, site branch, or package-numbered code/test comment was added.

## Remaining observations and limits

- **Full minute coverage is opt-in.** `f-first-minute-620.spec.ts` skips its all-site 60-second cases without `FIRSTMIN_AUDIT=1`. The opening/Journal/debrief journey in `journal-debrief.spec.ts` defaults to 10 seconds; `FLOW_AUDIT_SECONDS=60` extends it to 10/30/60. These tests were inspected, not executed here.
- **Scan UI coverage is not an unaided-piloting claim.** The two-objective journey in this checkout explicitly calls `setScanPose` before each scan. The longer opening journey labels its later assisted scan separately. `helpers/unlocked.ts` also seeds an experienced pilot for many legacy capability cases. Fresh Home/briefing/tutorial paths must be distinguished from these fixtures when assessing first-minute usability.
- **Free dive has no ordinary Surface and debrief action.** The pause action is installed only for missions; free dive can Quit to Home, and `?debrief=1` is a debug path. This is a product-flow question, not a proven strand, so it was left unchanged.
- **Phone/visual acceptance remains pending.** Actual 390×844 geometry, 150% scale, both orientations, documentary readability, scan reachability and real-phone Low/High responsiveness still require the owner checklist. No new screenshots, captures or manifests are offered as acceptance evidence. Existing numeric layout assertions were retained without loosening them.
