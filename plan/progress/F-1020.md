# F-1020 — Challenger Deep phone opening

## Changes

Challenger Deep and Endurance now use portrait-specific chase offsets: zero lateral
shift and a lower eye. The physics pitch was already zero; the apparent tilt came
from the oblique camera. The portrait hull is level and centred, with the seabed
and scan target visible. Free dives and mission starts carry the same override;
rotation, wheel zoom and camera reset preserve the dive's framing defaults.

The near-hull hint waits for 20 active dive seconds. It records the actual opening
depth only after props and POIs finish loading. If the opening was already in the
85% warning band, it remains suppressed at that depth and requires a further
10 m descent. A mission restart resets the baseline and grace period. Deferred
hints are not marked seen, and low-battery priority is preserved.

## Follow-up — E2E collection import failure

The orchestrator's unrestricted full gate passed build, unit, Python, content,
attribution, Prettier and project-base E2E, but the full E2E suite failed during
collection with `Cannot read properties of undefined (reading 'BASE_URL')`.
The new `Hints.ts` import of `core/Config.ts` pulled in UI configuration, whose
globe texture resolves through Vite's `import.meta.env`. Playwright collects
specs in Node without a Vite environment.

Reproduced the exact error inside the sandbox using `npx playwright test --list`,
which requires neither a preview server nor Chromium. Moved the guidance constants
into the environment-independent `src/core/config/guidance.ts` and made the pure
hint logic import that module directly. UI configuration re-exports the same
constant, preserving existing `core/Config.ts` callers and all tuning values.
The asset-base resolver and E2E assertions were not changed.

After the fix, `npx playwright test --list` successfully collects all 548 tests
across 77 files. The 41 focused hint, onboarding and camera-control unit tests pass.
Collection evidence: `.cache/f1020-e2e-collection-before.log` and
`.cache/f1020-e2e-collection-after.log`. The orchestrator failure log is preserved
in `.cache/f1020-orchestrator-e2e-import-failure.log`.

Full static revalidation is running via
`GATES_CONFIG_MODE=writable PW_PORT=4320 tools/gates.sh --no-e2e`; results are
recorded in `.cache/f1020-import-fix-gates.log`. Actual browser execution remains
for the orchestrator outside the sandbox; successful collection does not claim
that the browser tests or fresh golden captures have passed.
