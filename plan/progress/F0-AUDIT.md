# F0 audit — current build

Static code and content review, 2026-09-29. No browser run or new assets. The performance items are risks to measure on target devices, not measured frame rates.

## 1. Bugs

1. **High — Touch-only players cannot pilot.** `Input.attach()` listens to keyboard, mouse and gamepad, with no touch axes or action buttons (`src/core/Input.ts:510-521`, `src/core/Input.ts:603-624`). Add the virtual stick and action controls before calling the build phone-ready.
2. **High — Expanded sonar captures wheel input across the whole dive.** The capture listener checks only `sonar.expanded` and `appState`, then prevents the event (`src/main.ts:966-975`); scrolling the Journal, settings, briefing or globe can zoom sonar instead. Scope it to the sonar element and exclude modal overlays.
3. **Medium — Navigation and scan highlights can point to different POIs.** The router chooses the nearest unfinished primary (`src/game/MissionRouter.ts:259-283`), while waypoints and sonar use the first unfinished primary in file order (`src/main.ts:1595-1614`). Publish one shared active objective to all three views.
4. **Low — Error UI gives an unrelated fixed remedy.** Every startup failure calls `showFatal`, whose hint always says to fetch the Titanic tile (`src/main.ts:113-124`, `src/main.ts:1798-1800`), including failures unrelated to tile data. Show a tile-specific hint only for a `TileLoadError`.

## 2. Performance risks for phones and tablets

1. **High — Home boots and renders the entire dive.** Tile download, terrain meshing, material generation and 3D setup happen before home is shown (`src/main.ts:164-254`), and `frame()` renders the dive scene every frame even when `appState` is `home` (`src/main.ts:1332-1347`, `src/main.ts:1677-1694`). Defer dive creation and skip its render while home is active.
2. **High — Fixed 2× device pixel ratio has no frame-time feedback.** The dive renderer uses MSAA and up to DPR 2 (`src/main.ts:215-221`); the post pass adds a full-resolution scene target and screen pass (`src/main.ts:1680-1694`). Add mobile tier detection, dynamic resolution and GPU counters; measure at 30 m, 1,000 m and 4,000 m.
3. **High — Terrain load can hitch the main thread.** `Terrain` synchronously builds every chunk before first frame (`src/world/Terrain.ts:152-155`, `src/world/Terrain.ts:346-366`), with up to 4 million vertices (`src/core/Config.ts:1170`). Stage or worker-build chunks and expose loading progress before adding more scatter.
4. **Medium — Tile transfer is larger than necessary.** The default loader always fetches float32 (`src/world/TileLoader.ts:157-170`); the inventory lists a 5,774,408 B largest tile and 29,347,836 B for the 13 canonical float32 tiles (`docs/tiles-inventory.md:17-32`). Prefer the existing 16-bit variant, and avoid shipping unused variants in the site build.
5. **Medium — Three WebGL contexts and two globe textures can coexist.** Main creates one renderer; each globe creates its own on first open and loads the same 4096×2048 JPEG (`src/main.ts:215-221`, `src/main.ts:634-660`, `src/ui/Globe.ts:634-702`). Reuse one globe view or dispose the inactive context and texture.
6. **Medium — Terrain material is fragment-heavy.** Its shader does three triplanar reads for each of four maps, plus a depth-ramp read (`src/shaders/terrain.frag.glsl:54-59`, `src/shaders/terrain.frag.glsl:74-80`, `src/shaders/terrain.frag.glsl:94-106`); high tier also generates four 512² maps (`src/core/Config.ts:1172-1175`). Measure GPU time on low tier before adding PBR layers.
7. **Medium — Existing build size debt has no budget gate.** The archived build reports a 732.7 kB main JS chunk and Vite's 500 kB warning (`plan/archive/STATUS-before-2026-09-23-closeout.md:122`); Draco decoder files were also emitted twice, although props load from the public copy (`plan/archive/STATUS-before-2026-09-23-closeout.md:174-177`, `src/world/PropLoader.ts:312-324`). Recheck current output, split non-dive UI and exclude the unused decoder copies.
8. **Medium — Frame allocations scale with new content.** `getState()` clones two vectors (`src/sub/Submarine.ts:448-478`); the main loop allocates fog, scan-radius arrays, objective data and control-tip strings (`src/main.ts:1558-1592`, `src/main.ts:1595-1645`); sonar maps and filters markers every redraw (`src/ui/Sonar.ts:639-670`). Reuse scratch state and dirty-update the DOM before adding life and events.
9. **Low — Prop and preset entry can spike after the first frame.** `Props.placeAll()` starts every build at once (`src/world/Props.ts:200-225`), and `PresetSystem.tryEnter()` creates the site effect in one update (`src/world/presets/Presets.ts:398-422`). Time the largest content packs and spread optional visual construction across frames.

## 3. Fun gaps

1. **High — All 13 mission files use scan-only objectives.** The fixed site objectives all resolve through `type: "scan"` (for example `data/landmarks/great-blue-hole/mission.json:33-51`, `data/landmarks/titanic/mission.json:34-55`). Keep those fixed, but add optional samples, photos, secrets and ROV-only interactions with separate rewards.
2. **High — The named focus of one mission is absent from its objectives.** The Great Blue Hole mission asks only for east and west drop-off scans (`data/landmarks/great-blue-hole/mission.json:33-51`), and the [tile inventory](../../docs/tiles-inventory.md) flags the named feature as unresolved in the terrain. Add a hand-built, explicitly documented set piece and make it the hero discovery.
3. **Medium — Repeat dives have little progression.** Completion currently offers a tally and Journal entries (`src/game/MissionRouter.ts:595-635`); the persistent unlock check is scan-based (`src/game/JournalData.ts:202-217`). Award research, a 1–3 star rating and visible upgrades for discovery, care and optional finds.
4. **Medium — The ROV has no distinct objective role.** It shares the scanner with a reduced radius (`src/main.ts:1569-1592`), and no mission objective type calls for ROV use (mission JSON files under `data/landmarks/*/mission.json`). Give it one short interior or narrow-access task with a clear tether cue and return path.
5. **Medium — Species are mostly text unlocks.** Journal species unlock only when a linked POI is scanned (`src/game/JournalData.ts:169-183`, `src/game/JournalData.ts:207-217`); the dive loop has no life interaction path (`src/main.ts:1540-1668`). Make observing or photographing visible animals a direct discovery action.
6. **Low — Three top-level modes overload the first choice.** Home, briefing and settings all surface Arcade, Realistic and Custom (`src/ui/ModeSelector.ts:1-32`, `src/main.ts:1077-1093`). Default to Arcade, show Realistic beside it and move Custom to Advanced, while keeping the saved option values.

## 4. Code health for parallel work

1. **High — `main.ts` is the merge hotspot.** Its 1,800 lines mix startup, shell routing, controls, save listeners, ROV, photo, simulation and rendering behind old phase fences (`src/main.ts:35-97`, `src/main.ts:1230-1721`). Split into `src/app/AppContext.ts` (typed shared handles), `Bootstrap.ts` (load/init), `ShellSystem.ts`, `DiveSystem.ts`, `RovSystem.ts`, `PhotoSystem.ts`, `RenderSystem.ts` and `systems.ts` (ordered init/update/dispose registration); preserve the `window.__game` contract.
2. **High — `Config.ts` is another shared edit point.** Interfaces, profile definitions and the giant default literal live together (`src/core/Config.ts:9-1048`, `src/core/Config.ts:1049-1817`). Move type contracts to `src/core/config/types.ts` and defaults by domain to `vehicles.ts`, `world.ts`, `render.ts`, `gameplay.ts` and `ui.ts`; keep `src/core/Config.ts` as the stable re-export and `makeConfig` entry point.
3. **Medium — CSS append blocks make cascade changes hard to predict.** Base rules and later overrides for the same components are far apart (`src/styles.css:35-116`, `src/styles.css:1585-1719`, `src/styles.css:3695-3723`). Extract `src/styles/{tokens,shell,hud,mission,journal,settings,sonar,photo,globe,responsive}.css` and import them in a fixed order from `styles.css`; move each override with its component without changing selectors.
4. **Medium — Procedural builders share one 995-line file.** Wreck, debris, vent and texture helpers sit in `src/world/props/Procedural.ts:96-995`. Split into `src/world/props/builders/{wrecks,debris,vents,generic,shared}.ts`, with `Procedural.ts` retaining existing exports as a compatibility barrel; let each visual agent own one family.
5. **Medium — The same content is loaded by several UI paths.** Main loads summaries, two globes each load another catalogue, and separate code refetches mission hints (`src/main.ts:431-445`, `src/main.ts:536-600`, `src/main.ts:634-666`, `src/ui/GlobeModel.ts:201-219`). Create one immutable `ContentCatalog` with cached promises and typed objective hints, then pass it into shell, globe, Journal and mission systems.
