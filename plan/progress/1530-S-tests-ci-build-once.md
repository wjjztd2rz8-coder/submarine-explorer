# 1530 — S-tests step 4: build once per deployment base

Implemented the Step 4 design in `S-tests-map.md`. This changes CI/gate orchestration only; `tests/`, assertions, Playwright configuration, timing weights and discovery-driven shard selection are unchanged. Steps 2–3 and nightly capture selection remain separate work.

## Implementation

- CI has two independent `builds` matrix entries: `/` → `dist-root` and `/submarine-explorer/` → `dist-project-base`. Each installs the locked dependencies and runs one Vite build. Static checks typecheck once through the canonical runner; there are **two bundling builds instead of 32**, with no build/typecheck in consumers. Checks run independently so unrelated static work does not delay build uploads. Existing required status names are retained.
- `actions/upload-artifact@v4` publishes each complete output immediately after successful production, including hidden files, copied data/tiles, models, fonts and stamped PWA files. Immutable names are `ci-build-<run_id>-<run_attempt>-<root|project-base>`. Both browser jobs `needs: builds`; no consumer runs after a failed/cancelled matrix producer or downloads a different run/attempt.
- `ci-build-manifest.json` records checkout/workflow SHA, SHA-256 of `package-lock.json`, exact Node version, deployment base and outdir. `tools/ci-build-manifest.mjs` validates every field before discovery/preview and rejects missing manifests/output, mismatches, symlinks and missing essential public data/PWA files. Artifact v4 supplies immutable storage and its transfer digest; this is separate from npm/browser caching.
- Root consumers set `PW_OUTDIR=dist-root` and use the unchanged 30-shard balancer. Project-base consumes its own artifact at `PW_OUTDIR=dist-project-base`, with `VITE_BASE`/`PW_BASE=/submarine-explorer/`, port 4211, and direct Playwright selection of all eight base cases through the runner. It never invokes the rebuilding `test:e2e:base` package script.
- `npm run ci` delegates to `bash tools/gates.sh --full-e2e`. The runner's sole ordered list is Python → strict content → build/typecheck → unit → root browser → project-base build/browser → attribution → formatting. CI uses internal `--phase checks|build|e2e|e2e-base` entry points; browser phases require `--prebuilt` and an explicit retained output. Local smoke/full/no-e2e flags, writable configuration support, aggregated failure status, log names/links, per-run results, cleanup and owned strict-port previews remain supported. A failed local root build now explicitly blocks its browser gate rather than serving an old retained output.
- Run directories use `mktemp` so simultaneous sandbox processes with identical PIDs cannot collide. Temporary Vite configuration uses that unique run ID. Hosted phases stream output while retaining the usual gate logs.
- Fail-fast remains false, branch/PR cancellation remains enabled, and CI low-tier seed, one worker, one retry, bounded Chromium/OS installation, all existing budgets, per-shard JSON timings and failure-report uploads are preserved.
