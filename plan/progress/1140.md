compare the resulting checkout with f43, including those follow-ups.

Confirmed defects and fixes:

1. **Lost City mineral blend used reversed smoothstep edges.**
   `smooth(0.5, 0.3, mineral)` does not produce a descending smoothstep in
   Three.js. It jumps from zero to one above 0.5, abruptly introducing grey-blue
   tint on the wrong side of the noise field. Use
   `1 - smooth(0.3, 0.5, mineral)`. A regression controls only the mineral noise
   in the actual tower builder: before the fix, a 0.000002 noise change caused
   a **0.46668** vertex-colour jump; the unchanged new threshold is < 0.0001.
2. **Every Beebe rock emitted an avoidable Three.js warning.**
   `IcosahedronGeometry` is already non-indexed; calling `toNonIndexed()` warns
   for every block. Remove that call and retain the existing duplicated corners,
   flat normals, paint and triangle count. Low's authored apron emits 11 warnings
   per construction before the fix and zero after. A regression requires silent
   construction, finite buffers, identical per-face normals and unit normals.
3. **An irregular spire with `topFrac: 0` generated NaN positions/normals.**
   The legacy shelf blend divided its zero tip radius by itself. Preserve a zero
   radius before that division. This is a pre-existing shared edge case discovered
   during the profile audit, not a claim that shipped towers currently have NaNs.
   Test both the legacy irregular and opted-in trunk paths at zero tip radius.
4. **Avoidable setup allocations.** Hoist the terrace-free spire options out of
   the vertex loop; construct Monterey's new hardness/colour table only for canyon
   scarps. Other scarp profiles do not use it. Authored geometry is unchanged.

## Round 2: isolation, budgets and coverage

`tests/unit/terrainMerge1140.test.ts` adds **10 tests** and four new Low-tier
snapshots. These check all authored props at each affected site, every geometry
attribute, index/instance buffer fingerprints, finite values and exact static
prop draw counts. Triangle ceilings preserve Blue Hole / Monterey's f43 costs,
allow Lost City's reduced count, and pin Beebe's already-merged +660 triangles.
This does not change the existing Beebe snapshot or any earlier assertion.

Two additional byte-level checks compare tuff and hadal scarps with f43 buffers
(position, normals, colour and other attributes), catching Monterey gating leaks.
Both retain their exact baseline hashes. The existing Beebe isolation snapshot
checks its chimney/collision/vent anchors across all four tiers, so the Lost City
trunk flag stays off Beebe. Existing gallery envelope, Low/high costs, Monterey
frame budget and Lost City surface checks also pass in the focused run.

Numeric review: Monterey bed intervals remain strictly positive (minimum 0.3),
and bed hardness/palette lookups clamp to the authored band count. Blue Hole
pendant inverse taper stays at least 0.07 and east-mouth lengths below 0.5 m
are skipped. Jittered terrace fractions use `u - floor(u)` before fractional
powers, including negative noise phases; shipped Low buffers are all finite.
The zero-radius legacy spire division was the confirmed NaN edge case.

No new draw calls were found. The Beebe builder remains opt-in via its authored
id/feature/extension; generic talus users retain the default lump builder and lift.
Monterey displacement/paint is canyon-only. Blue Hole tint remains attached to
its biome; the separate pendant PRNG preserves placement. Lost City trunk is an
explicit option rather than a change to every irregular smoker.

The changed noise/profile/paint functions run during geometry construction.
`Terrain` consumes `vertexTint` in mesh construction; `Terrain.update` and
`Props.update` have no changes since f43. No new per-frame allocations were
introduced by these diffs. This is a source finding; a browser heap/frame trace
is still needed to measure runtime GC and rendering costs.

## Remaining work

- **Lost City Low generation:** the two comparisons indicate roughly 20–24%
  more prop construction CPU despite reduced triangle counts. Profile the added
  trunk/multi-octave vertex-paint/roughening work on an idle runner and a phone;
  consider caching ring-constant noise or reducing redundant evaluations while
  retaining geometry and colour contracts. No art/tier reduction attempted here.
- **Blue Hole real-tile generation:** about 11% slower in the real-tile comparison.
  Repeat without concurrent tests and profile the new per-tread search/tint work
  over the full tile before treating that timing as a confirmed regression.
  Beebe/Monterey terrain timing changes need the same idle-runner confirmation.
- **Rendered performance and visual acceptance:** measure actual frame draws,
  triangles, frame time and heap/GC over Low desktop and phone gallery/tower/rock/
  canyon approaches. Inspect the Lost City blend correction and vent mouths,
  Beebe apron feathering from above, and thin Monterey beds. Static buffer
  snapshots do not substitute for image snapshots or a rendered frame budget.
- **Coverage still missing:** dedicated generation-time benchmarks on a controlled
  runner; visual snapshots for these four art changes at Low desktop/phone;
  aggregate authored buffer snapshots for the remaining tiers. Existing all-tier
  Beebe isolation and other higher-tier geometry tests remain in force.
