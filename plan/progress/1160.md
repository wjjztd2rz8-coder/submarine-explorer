## Review and regression coverage

`tests/unit/debriefReopen.test.ts` now checks the 0 → 1 → 0 scan transition
using the real Debrief implementation, exact action order and callback wiring:

- Zero scans with resume available: one filled **Keep exploring** primary;
  quiet **Dive sites**, then **Journal**; **Dive again** and **Home** under More.
- One scan: one filled **Dive sites** primary; quiet **Keep exploring**, then
  **Journal**; the same More actions.
- Every rebuilt summary resets More to hidden with `aria-expanded="false"`.
  Caller action order remains unchanged.
- Zero scans without resume: existing **Dive sites** primary. Default free-dive
  actions retain **Dive again** primary. No unusable resume action is introduced.

These are DOM unit checks, not visual or browser accessibility acceptance.
Static review confirms MissionRouter resumes through the existing mission
state transition, hides the debrief, restores the objectives panel and forces
a navigation refresh. FocusTrap deliberately blurs on opening; the first Tab
enters the primary control rather than automatically focusing it, to avoid
held flight keys activating a button.

Added `tests/e2e/f-debrief-zero-1160.spec.ts`, discovered as six cases. Each
case keeps Arcade as the default, uses only Low graphics for rendering, and
surfaces at zero scans, resumes, completes exactly one assisted POI scan via
the existing held-key/geometry/event helper, then surfaces and resumes again.
The helper is not a natural scan-duration audit.

The spec asserts exact primary/secondary actions; no panel overflow; forward
and reverse focus wrapping; expanded More order; stacked Journal focus and
return; frozen mission/session clocks and pose while surfaced; exact state,
pose, scan and objective preservation on resume; resumed timers and movement;
HUD/objectives visibility; fresh More state on reopening; Escape resume; and
Dive sites → Home navigation. It captures debrief and resumed HUD screenshots
for every site, size and scan count. Assertions in existing specs were not
loosened. The new browser spec has not executed and needs runtime validation.
