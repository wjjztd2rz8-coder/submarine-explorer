# Phase D contracts — playability

Applies to the package order in [PHASE-D-PLAN.md](PHASE-D-PLAN.md) §3. Schema and event names below are binding; each implementation brief reports a deviation before relying on it. Earlier data and source honesty rules still apply.

Existing display fields keep their current types, validation and defaults; `uiScale` is an integer percent in `[80,150]`, default `100`. `bindings` points to `subexplorer.bindings.v2`. `gameplayMode: 'arcade'|'realistic'|'custom'`; `gameplay` has **all** fields below, never a sparse override. `Config.settings.gameplayPresets` and `Config.settings.gameplayOptions` are the sole preset/range source, with numeric physics tables in `Config.speedProfiles`, `Config.lightPresets`, `Config.sensorPresets`; `makeConfig` must merge the new sections. Existing defaults and the current v1 shape: `src/core/Save.ts:23-50`, `src/core/Config.ts:897-947`, `src/core/Config.ts:1356-1369`.

- `Save.load`: read v2 first. If absent, sanitize v1 using its existing rules, copy its seven display values, assign Arcade preset and `uiScale=100`, write v2 once if storage permits; leave v1 intact. Missing/invalid v2 fields fall back individually, unknown future version stays read only as now (`src/core/Save.ts:189-207`). `reset()` restores v2 defaults. `simSpeedDefault` remains for legacy display migration but `gameplay.simSpeed` wins when launching a dive; Settings must label the older control accordingly or fold it into the new control.
- Choosing Arcade/Realistic replaces the entire gameplay object atomically. Editing **any** gameplay option, even to a preset's current value, sets `gameplayMode='custom'` and keeps every other value. Choosing Custom alone copies current values; it never guesses a preset. Display, accessibility and `uiScale` changes do not change the gameplay label. If v2 says Arcade/Realistic with mismatched values, load the named preset. Invalid Custom values sanitize field by field. Emit one `settings:changed` per changed key via the existing event (`src/core/EventBus.ts:69-71`).
- Physics values are **1× simulated time**. Display speed in both m/s and kn (`kn = m/s / 0.514444`); 2×/3× sim speed changes travel per wall second, not the displayed vehicle speed (`src/sub/Submarine.ts:244-249`). The fast profile is intentionally a game capability across existing hull classes, not a claim that Alvin can reach it.

## 2. Input, camera and HUD

The action IDs in `Input` remain the public map except `ping` is removed. New defaults use `KeyboardEvent.code` (`src/core/Input.ts:66-85`, `src/core/Input.ts:87-174`).

| Action                  | Keys                                 | Action               | Keys                                            |
| ----------------------- | ------------------------------------ | -------------------- | ----------------------------------------------- |
| Ahead / astern          | `KeyW` / `KeyS` (arrow aliases kept) | Yaw port / starboard | `KeyA` / `KeyD` (arrow aliases kept)            |
| Nose up / down          | `KeyR` / `KeyV`                      | Ascend / descend     | `Space` / `ControlLeft`, `ControlRight`, `KeyC` |
| Boost / scan (hold)     | `ShiftLeft`, `ShiftRight` / `KeyF`   | Lights / sonar map   | `KeyL` / `KeyM`                                 |
| Camera view / sim speed | `KeyQ` / `KeyT`                      | Journal / photo      | `KeyJ` / `KeyP` (photo hidden until D-PHOTO)    |
| Pause menu              | `Escape` (reserved, not rebindable)  | Dive sites           | menu entry only; retire `KeyN`                  |

- Bindings key becomes `subexplorer.bindings.v2`, `{version:2, keys: Record<ActionId,string[]>}`. If v2 absent, read v1 (`src/core/Input.ts:176`, `src/core/Input.ts:309-360`), preserve each user's **nondefault** v1 assignment by comparing it with the old default table, then fill all untouched actions from the D defaults. Explicit empty arrays stay empty; resolve duplicate codes once with saved custom choices first. Drop `ping`; map old `toggleGuide` to `toggleJournal`. D-INPUT+HUD may keep `toggleSettings: KeyO` and `toggleGlobe: KeyN` as **undisplayed temporary actions** to keep the gate green before D-SHELL lands. D-SHELL retires them from the live map and routes their UI through Esc/home; ignoring those obsolete v2 entries requires no schema bump. Save v2 after migration; leave v1 intact. Unknown future versions stay untouched; Reset keys clears v2 and returns D defaults. `Save.bindings` points at v2.
- Browser Ctrl+W cannot be intercepted in an ordinary tab: C is a full descend alias. On entering fullscreen, call `navigator.keyboard.lock(['ControlLeft','ControlRight','KeyW'])` when supported; unlock on fullscreen exit, rejection, pause or teardown, and never assume success. Show a one-time dismissible tip on first Ctrl descend: “Ctrl+W may close this tab. Use C or fullscreen.” Store its dismissal in `subexplorer.tips.v1` (`{ctrlW:true}`); support absent storage. Reserve Escape for closing the top modal then pause; Settings' current reserved keys are at `src/ui/Settings.ts:31`.
- Default camera control is **left-button drag over canvas** (no pointer capture on UI); wheel over canvas changes chase radius, `clamp(35,180)` m. Optional pointer lock is explicit in Controls and only from a user gesture; Escape releases it before opening pause. Apply drag orbit in chase and first person, suppress while menus open, retain gamepad support. Current mouse look is first person only and chase offset is 115 m (`src/main.ts:459-463`, `src/core/Config.ts:1207-1227`); D default chase offset is `{x:0,y:24,z:65}` m. Respect `reduceMotion` by removing camera easing/shake, not control response.
- HUD root uses CSS custom properties `--ui-auto-scale`, `--ui-user-scale` and `--ui-scale: calc(var(--ui-auto-scale) * var(--ui-user-scale))`; set the numeric auto value on viewport resize to `clamp(innerWidth/1920, 0.8, 1.25)` and user factor to `uiScale/100`. Clamp the resulting HUD font sizes in CSS, with body text ≥14 px at 1920×1080; do not scale the WebGL canvas. Compact HUD fields: depth, m/s+kn, heading, hull, one objective, contextual F prompt, non-1× badge. Remove `.hud-help` and docked mission select from dive (`src/ui/HUD.ts:35-61`, `src/main.ts:308-325`). CSS remains in `src/styles.css` with package fences.

## 3. Mission content and start

- Every `data/landmarks/<id>/mission.json` objective gains required, nonblank `hint: string` after D-CONTENT; sentence says **what and roughly where** using existing POI/guide evidence, with no fabricated exactness. Keep mission schema `version:1`. `parseMission` passes `hint` through to `ObjectiveStatus`, briefing and panel; validator treats missing/blank as error for all 13. Current parser/validator: `src/game/Mission.ts:40-47`, `src/game/Mission.ts:121-145`, `tools/validate_landmark.py:431-459`.
- Existing `spawn` remains the surface pose, for compatibility. Optional `start?: {near_site?: {lat:number,lon:number,depth_m:number,heading_deg:number}}` on the mission root is a **content override only**; D-START computes near-site pose from first resolved primary POI when absent. Reject invalid override with a validator error. If present, its coordinates must be inside tile, depth safe for `hull_class`, and ≤200 m horizontally from that POI; do not require D-CONTENT to add it. `MissionRouter.applyMissionLoadout` currently always uses `def.spawn` (`src/game/MissionRouter.ts:136-154`); chosen briefing start option overrides saved default for this launch only. Near-site uses 100–200 m offset, ≥`hullRadius+seabedClearance+spawnClearanceM` above seabed, aims toward target, and keeps `?poi=`, `?at=`, `?depth=` debug overrides (`src/main.ts:195-213`, `src/game/Discovery.ts:117-135`). Lights start on.
- No `mission.json` version bump for additive `hint`/`start`. Start validation must use a fixed time budget: first primary reachable in ≤60 s at Arcade fast cruise under a straight safe approach; report exceptions with reason.

## 4. Scans, Journal and dive flow

- `scannedThisDive: Set<"<landmark>/<poi>">` is memory only, cleared at every start/restart/new route. It drives world marker/sonar/objective completion and bars another scan **during this dive**. `loggedInJournal` comes from `DiscoveryStore.isDiscovered` and remains true across reloads; it does **not** precomplete objectives or bar a fresh dive's scan. Current scanner only prevents rescans until release (`src/game/Scanner.ts:114-117`, `src/game/Scanner.ts:157-168`); current `Objectives.progress()` reads persistence (`src/game/Objectives.ts:54-80`). Prompt: F Scan only for in-range unscanned; “Already logged — see Journal” for scanned-this-dive; no prompt for out-of-range. Keep `scan:complete.firstTime` meaning first **ever** in Journal (`src/core/EventBus.ts:39-45`).
- Journal **reuses** `subexplorer.discoveries.v1` unchanged: `{version:1, discovered:{"<landmark>/<poi>":{at:ISOString,count:number}}, stats:{scans:number,firstAt?:ISOString}}` (`src/game/DiscoveryStore.ts:4-36`). Entries per site, POI and species are derived from `landmarks.json`, `guide.json`, `pois.json`, `species.json`; site unlocks on any POI scan; species unlocks only when its documented POI/guide linkage is scanned. Entries with no linkage stay spoiler-only until a future encounter system. “Show undiscovered entries (spoilers)” is an **in-memory UI toggle**; no new persisted schema. D-PHOTO may add separate `subexplorer.photos.v1`, and must not change discovery v1. Keep store's future-version read-only rule (`src/game/DiscoveryStore.ts:151-159`).
- `MissionState` becomes `briefing → diving → primaries-complete → debrief`, plus `aborted → debrief` after emergency ascent. Primary scan emits `mission:primaryComplete:{missionId,completed,total}` and shows “Primary objectives complete” with Keep exploring (dismiss banner, stay `primaries-complete`) / Surface and debrief. Secondary scans remain valid. All objectives done may suggest surfacing, but never auto-open debrief. `mission:complete:{missionId,durationS}` fires **once**, on voluntary surface/end after primary completion; `mission:ended:{missionId,reason:'surface'|'all'|'abort',completed,total,durationS}` fires on every debrief transition. Keep existing `mission:started`, `mission:objective`, `mission:restart`, `mission:aborted` payloads. Present `X of Y objectives` in debrief. Current timer auto-completes and opens debrief (`src/game/Mission.ts:342-355`, `src/game/MissionRouter.ts:401-405`); remove that behavior.
- Debrief buttons: Keep exploring closes debrief and resumes the same state/pose (absent for abort); Dive again resets scan/objective/session stats and navigates to same mission with briefing unless test URL says skip; Dive sites opens mission select/globe without launching; Home opens home. Journal opens from debrief as a fifth action. Existing Dive sites navigates `/` (`src/game/MissionRouter.ts:424-473`), and old `Discovery.debrief` is separate (`src/game/Discovery.ts:90-95`); consolidate navigation behavior without double overlays.

## 5. App shell, events and ownership

App shell states: `home ↔ dive ↔ pause`; briefing and debrief are dive subviews, with only one top modal handling Escape. Plain `/` shows home with C1 globe as its site selector; it may load the default tile behind it but physics/audio stay paused. `?mission=`, `?tile=`, or `?skipBriefing=1` bypass home; `?poi=`, `?at=`, `?depth=`, `?debrief=1`, `?globe=1` also bypass for existing debug/e2e routes. `?globe=1` opens the existing globe over the dive. Continue uses `subexplorer.lastSite.v1` (`{missionId:string}`), saved when a mission starts; absent → disable Continue. Free dive opens tile/site choice; Dive sites and globe pin launch preserve current `missionUrl`/`tileUrl` mapping (`src/ui/MissionSelect.ts:43-62`, `src/ui/Globe.ts:258-315`). `app:state:{state:'home'|'dive'|'pause'}`, `app:siteSelected:{missionId:string|null,tileId:string}` are added to `GameEvents` (`src/core/EventBus.ts:15-72`). Escape from pause resumes; Quit to home freezes and returns to home. Existing globe is an overlay, `src/main.ts:314-328` and `src/ui/Globe.ts:258-271`.

`main.ts` has old B/C comments, not D fences. Add **one bounded `// --- D-<PACKAGE> begin/end ---` block per integration point** below; no package edits another's D fence. Later sequential packages may call prior public APIs _outside_ another fence; if a new call must be inside one, report a contract change before editing. `src/styles.css` additions likewise use `/* --- D-<PACKAGE> --- */`. `src/core/EventBus.ts` additions are additive by owner.
